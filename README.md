## 제작 배경

제안요청서 기반 RAG 프로젝트에서 HWP 문서를 다루며, 일반 텍스트 변환이나 기존 변환 방식으로는 문단의 배치와 표·병합 셀 구조가 깨져 결과물을 다시 편집하거나 데이터로 활용하기 어렵다는 문제를 확인했습니다.

변환이 실행됐다는 사실보다 **문서가 가진 관계를 얼마나 살려 다시 사용할 수 있는가**가 더 중요하다고 보았습니다. 이 문제의식을 HWP·HWPX 변환 서비스로 확장하고, 반복해서 필요한 PDF·이미지 작업도 한곳에서 처리할 수 있도록 FormatPop을 만들었습니다.

## 해결 목표

- 문단 순서와 표의 행·열, 병합 셀 등 문서 구조 보존
- 변환 결과를 다시 편집하고 활용할 수 있는 형태로 제공
- 불필요한 원본 파일 전송과 서버 처리를 줄이는 구조
- 파일 선택부터 결과 다운로드까지 이어지는 사용 흐름
- 처리 위치와 지원 범위, 변환 후 확인 사항의 명확한 안내

## 현재 제공 기능

- HWP·HWPX → 워드·PDF·TXT·Markdown 변환
- 워드 → HWPX·PDF·TXT·Markdown 변환
- HWP·HWPX 뷰어, 워드 뷰어, 두 파일 나란히 보기
- PDF 합치기·분할·페이지 추출·회전·이미지 변환
- 이미지 형식 변환·용량 축소·크기 조절과 OCR
- 변환 원리와 오류 원인을 다루는 문서 가이드와 개발 기록

현재 한글 파일·문서·뷰어·PDF·이미지 영역에서 **29가지 무료 파일 도구**를 제공합니다. 실제 문서에서 발견한 구조 손실을 재현하고, 원인을 확인한 뒤 회귀 검증 항목으로 남기는 방식으로 개선하고 있습니다.

## 설계 판단

### 문서 구조를 먼저 복원하는 변환

HWP·HWPX·DOCX는 문단, 글자 모양, 표, 병합 셀, 그림, 용지와 여백 정보를 서로 다르게 표현합니다. FormatPop은 글자를 바로 출력 형식으로 복사하지 않고, 입력 문서의 관계를 공통 문서 구조로 복원한 뒤 워드·PDF·HWPX 등 각 결과 형식에 맞게 다시 구성합니다.

이 과정에서 표의 행·열, 열 너비와 행 높이, 병합 범위, 셀 안의 문단과 중첩 표, 그림의 기준 위치를 함께 다룹니다. 출력 형식이 달라도 같은 해석 결과를 활용할 수 있어, 한 형식의 수정이 다른 변환 경로와 충돌하지 않도록 구성했습니다.

### PDF의 두 가지 출력 방식

PDF는 원본의 위치 정보가 충분한 문서와 그렇지 않은 문서를 같은 방식으로 처리하면 내용 누락이나 불필요한 빈 페이지가 생길 수 있습니다. 위치 정보가 충분하면 원본 좌표를 활용해 레이아웃을 재현하고, 안전하게 재현하기 어려우면 문서 흐름에 따라 내용을 이어 배치하는 방식으로 전환합니다.

고정 레이아웃 결과의 구조와 내용을 확인한 뒤 사용할 수 있을 때만 채택하고, 그렇지 않으면 흐름 기반 결과로 대체해 일부 내용이 사라지는 위험을 줄였습니다.

### 브라우저와 서버 처리의 분리

PDF·이미지처럼 브라우저에서 안전하게 처리할 수 있는 작업은 가능한 한 사용자 기기 안에서 실행합니다. HWP·HWPX 변환과 같이 별도 해석 과정이 필요한 작업만 서버에서 처리하며, 입력 파일과 결과 파일은 영구 보관하지 않습니다. 이 구분으로 파일 전송 범위와 서버 연산 비용을 함께 줄였습니다.

### 회귀 검증

새로운 오류가 발견되면 같은 구조를 비민감 자체 문서로 다시 만들고 검증 표본에 추가합니다. 문단과 이미지의 순서, 표의 행·열과 병합 범위, 본문 내용, 페이지별 결과 화면을 자동 검사와 육안 비교로 확인합니다.

### 사용 흐름과 안내

도구를 종류별로 나누고, 파일 선택·옵션 설정·처리 상태·결과 다운로드가 한 흐름으로 이어지도록 구성했습니다. 지원 범위와 파일 처리 방식, 변환 뒤 확인할 사항을 가이드로 제공해 사용자가 결과를 직접 판단할 수 있도록 했습니다.
